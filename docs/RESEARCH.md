# 研究方法、資料分層與覆蓋缺口

目標是建立持續擴大的全球開源省錢資料庫：能從原本的付費工具找到候選，說清楚可以取代什麼、哪些費用仍存在，以及下一步怎麼確認。**「世界最完整」是長期目標，目前沒有足以證明全球第一的同口徑比較。**

## 三種資料，三種用途

| 資料 | 怎麼用 | 已做到什麼 | 尚未證明什麼 |
|---|---|---|---|
| `data/products.json` 整理候選 | 按用途、平台與原軟體選擇 | 官方資料閱讀程度、個別日期、授權、費用、繁中／英文用途及限制 | 真機可用、遷移成功、台灣口音準確度、實際節省 |
| `data/upstream/awesome-selfhosted/index.json` 廣域索引 | 發現目錄以外的自架軟體 | 固定上游版本、名稱、分類、網址、上游授權與逐筆出處 | 每個專案的現況、免費版、安裝難度與實際替代能力 |
| 國內外文章／論壇／目錄 | 找新領域、經驗、爭議與比較方法 | 原文連結、閱讀範圍、原創摘要、選出的候選與限制 | 文章中的全部主張都是最新或正確 |

三種資料會重疊，數量分開列，不能直接相加。同一工具的 Windows／Mac 版本、雲端版入口、鏡像 repo、前端不拆成額外產品；Community 與 Enterprise 的功能界線在同一筆候選內說明。不同軟體即使都是某套裝的一部分，節費仍只能按可取消的帳單計算。

## 如何研究得更廣

先用「工作領域 × 原付費工具 × 部署方式 × 地區語言」找空白，再重用別人的整理。搜尋結果不是研究結論，先閱讀相關段落，再把候選回查到官網。

| 搜尋軸 | 本輪補足方向 | 繼續擴充的具體問題 |
|---|---|---|
| 創作與工程 | 向量、出版、字型、RAW、相片管理、2D 動畫、CAD、EDA、音樂、GIS、統計 | 能否交換客戶的原始專案？外掛、字型、色彩、樂器素材是否另有授權？ |
| 企業營運 | 專案、CRM、ERP、客服、表單、排程、電商、網站分析、Wiki、自動化 | Community 缺哪些角色／稽核／單一登入功能？台灣稅務與電子發票是否需另接服務？ |
| 個人與開發 | 備份、遠端、檔案、隱私、API、資料庫、本機 AI、記帳、RSS、文獻 | 有官方穩定安裝版嗎？備份可還原嗎？同步／模型／代管費是多少？ |
| 地區與語言 | 繁中、簡中、英文、法文、德文、日文來源 | 地區文章能提供何種本地工作情境？介紹有中文不等於軟體有繁中介面 |
| 平台 | Windows、macOS、Linux、瀏覽器與自架 | 伺服器跑 Linux 不等於使用者要安裝 Linux；iPad 需另核對瀏覽器及輸入限制 |

先找同類比較文章，再找失敗經驗與官方限制。對高重複領域，例如螢幕錄影，不因新貼文就一直增加相似項目；優先補缺少的用途。對沒有符合條件的工具保留缺口，不用試用版或停維護專案湊數。

## 如何研究得更深

每一個要升級為整理候選的工具，至少回答：

1. **要省哪一筆支出？** 指定原軟體和實際工作，分清楚全套、單一模組與基本功能。
2. **實際拿到什麼？** 官方下載、可自架原始碼、命令列工具或僅有 API；核對 OS、架構與穩定版本。
3. **免費範圍在哪？** 原始碼授權、官方安裝包、雲端方案、商用、企業功能、模型／素材／API 分開檢查。
4. **工作落差在哪？** 找至少一項會影響遷移的格式、外掛、角色權限、同步或服務差異；未知直接標示。
5. **誰的證據？** 文章發現、官方完整／局部閱讀、使用者經驗、可重現實測各自記錄，不借用別人的測試冒充本專案已測。
6. **用什麼任務驗收？** 指定一份真實文件、一個小型專案、一次備份還原或一段輸出，記版本與結果。沒執行前保持 `runtime_tested: false`。

重要的變動會比星數更影響選擇：維護模式、beta、封存、改授權、商業版拆分，以及免費方案縮減。逐項日期留在產品資料，資料集更新日期不會覆蓋沒重查的舊證據。

## 已讀文章如何進入資料庫

`data/research-sources.json` 記錄新增國內外來源，舊文章保留於 `data/article-sources.json`，論壇經驗保留於 `data/community-sources.json`。每個新來源有 publisher、language、region、read_status、review_scope、topics、selected_candidates、原創摘要與 caveat。

`scripts/build_research.py` 會把已收錄的候選名稱連回對應工具分類，更新舊 `discovery.json` 的收錄去向，並產生研究來源頁與統計。仍無對應的名稱只是待查線索。

只摘要與連結一般文章；不抄全文、不把他人描述套成本專案測試。大型資料匯入先確認再利用條款。本輪 Awesome Selfhosted 衍生索引採 CC BY-SA 3.0，完整保留來源版本、AUTHORS 與 LICENSE；它的軟體授權欄只是上游回報，推薦前仍需回查。

## 離線搜尋與重建

```bash
python3 scripts/saver.py search "Jira" --platform web
python3 scripts/saver.py search "備份" --platform macos
python3 scripts/saver.py discover "知識庫" --limit 20
python3 scripts/saver.py discover "CRM" --limit 20 --json
python3 scripts/saver.py validate
python3 scripts/build_catalog.py
python3 scripts/build_research.py
python3 -m unittest discover -s tests -v
```

`search` 查整理候選；`discover` 查上游線索。兩者都不連網。廣域搜尋以名稱、別名、上游分類與明確的中英關鍵字對照工作，不是自然語意搜尋，也不會自動判斷適合你的替代品。查看全部上游資料及重建方式：[索引說明](../data/upstream/awesome-selfhosted/README.md)。

## 持續維護與尚未涵蓋

以下是維護規則與研究優先順序，**不代表已啟用排程或自動實測**。

| 優先順序 | 觸發／研究工作 | 完成條件 |
|---|---|---|
| P0 | 回報重大授權、封存、失效下載或免費方案變動 | 回查官方、修正或降級相關候選，保留原因與日期 |
| P1 | 高使用量替代關係缺驗證 | 完成代表性匯入／編輯／匯出／復原；保留失敗項目 |
| P1 | 擴充 Android／iOS 與真正可商用的在地方案 | 補平台、安裝方式、繁中／商用證據；不借用桌面版結論 |
| P2 | 教育、無障礙、農業、法律、醫療、製造、GIS 等垂直工作 | 先找到具體付費工作，再找維護中的現成工具；行業合規能力另驗證 |
| P2 | 新增西語、葡語、韓語、阿拉伯語等來源 | 每種來源有實際閱讀範圍、提取候選、官方回查與獨特增量 |
| P2 | 自架目錄以外的桌面與行動大型上游 | 先核對資料再利用授權，再做去重匯入與差異報告 |
| P3 | 上游新版本 | 固定 commit 重建，核對新增、移除、非自由標記及授權改動；不覆蓋人工查核結果 |

每次研究以新增領域、真正可用的條件對照、已處理矛盾與完成的驗收任務衡量，不以搜尋次數或下載清單筆數代替品質。資料量成長與工作流品質要各自有證據。
