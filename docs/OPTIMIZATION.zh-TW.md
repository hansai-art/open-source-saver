# 開源省錢管家 v0.2 優化規格

日期：2026-09-11 · 狀態：規格定稿，功能待依里程碑實作

[English](OPTIMIZATION.en.md) · [現行 Spec](SPEC.zh-TW.md) · [驗收狀態](STATUS.md)

## 1. 決策與範圍

定位維持「先找現成工具，再判斷能不能替換」。優先服務台灣一般使用者及影音創作者，接受免費非開源軟體。先擴充資料與查核流程，不開發新的錄影、轉錄、字幕引擎，不另做帳號系統、雲端資料庫或桌面 App。

沿用 GitHub、Markdown、JSON、現有搜尋與盤點程式。第一個公開版本仍為 v0.1.0-alpha；本文件的 v0.2 目標不表示功能已完成。58 個產品、14 組對照、11 篇文章是現況；53 個文章發現名稱與產品有重疊，不能加總。

## 3. 規模目標與收錄門檻

v0.2 目標為至少 200 個去重的發現候選、80 個完成最小官方查核的產品、40 組付費軟體或任務對照。這些是目標，不是現有成果，也不是為了達標降低門檻。

發現候選需有名稱、原始來源、任務、發現日期；不能直接變成推薦。最小官方查核需有官網、官方取得入口、支援平台、免費取得條件、授權或使用條款來源、至少一項核心用途與限制。缺欄者留在發現區。功能測試另列，不把讀文件視為實測。

同一產品的別名、版本、作業系統與桌面／網頁版不重複計算產品數；不同方案保留 edition。更名、停更與分支用 canonical_id、previous_names、related_project 關聯，不能只靠相似名稱合併。

先完成以下 20 個任務樣本：長課程錄影、教學自動縮放、短錄影分享、截圖標註、長截圖、OCR、語音打字、長音訊轉錄、多人逐字稿、字幕校對、繁中字幕匯出、TTS 配音、靜音剪輯、無損裁切、轉檔壓縮、音訊降噪、修圖、向量繪圖、Office 文件、PDF 編修。每個至少覆蓋 Mac、Windows 其中一個明示平台；每項強制記錄其他平台的已知缺口。

## 5. v2 資料契約

保留現行 schema v1，新增 schema v2 前須提供可重現遷移；原始 ID 不變。

產品必要欄位：id、canonical_name、aliases、category、platforms、official_url、acquisition_url、delivery、cost_type、source_license、commercial_terms、localization、claims、sources、status。

- delivery：builtin、desktop-binary、browser-extension、web-service、self-hosted、source-only、engine；同產品可有多個 edition。
- cost_type：free、freemium、paid、trial、unknown。另記免費版限制與須付費項目；未知不能當免費。
- localization：docs_zh_tw、ui_zh_tw、chinese_content、taiwan_speech，各自 yes／no／partial／unknown；須附對應證據，語音實測另附方法。
- claims：feature、value（yes／no／partial／unknown）、edition、platform、source_url、checked_on、tested_on（可空）、test_notes（可空）。
- sources：url、kind（article／official／runtime）、checked_on、reuse_notes。文章可證明它推薦過什麼，不足以單獨證明目前免費條件。
- status：discovered、documented、workflow-tested、stale、archived；workflow-tested 必須附平台、版本、任務與結果，不能只給布林值。

關係資料獨立存放：source_name／task_id、aliases、target_id、replaces、does_not_replace、required_setup、evidence。某工具能錄影，不等於能替換錄影、運鏡、字幕及分享的完整工作流。

遷移時，不從 license 字串猜 cost_type，不把既有 zh_tw=unknown 填成已支援；無法對應欄位保持 unknown。舊 schema 仍可查詢，v2 在另一檔案驗證後切換，保留回復版本。

## 6. 推薦流程與排序

1. 只取得會改變建議的資訊：系統、原工具或任務、必要功能、可接受部署方式。資訊足夠立即查詢。
2. 先查內建功能與資料快照，再利用文章、目錄和官網補缺。嚴格離線時不連網、不讀私人檔案進雲端。
3. 必要條件先過濾；未知或不支援列為待查，不能進「已符合」結果。
4. 通過後依安裝容易、免費範圍清楚、繁中適用、交付相容性、維護證據排序。不用星數或虛構百分比取代判斷。
5. 先列最多三款，說明替代哪些功能、不能替代什麼、取得方式與一次試用任務。只有具體缺口才再擴搜一輪。
6. 沒有合格者，允許保留付費工具或提出分段組合，並標示組合尚未驗證。不自動安裝或取消訂閱。

輸出欄位：建議等級、工具、用途、平台、費用類型、繁中狀態、官方取得入口、限制、證據日期、試用任務。實際省錢需使用者提供可取消支出；套裝不重複加總。

## 7. 更新與品質

初期採需求驅動更新，不建立自動排程。推薦當下重查免費、下載與必要功能；超過 30 天的這些證據標示待重查。連結失效先留狀態與歷史，不直接刪除產品；停止維護不等於無法使用，但須列維護風險與來源。

每次變更檢查：ID 去重、別名衝突、來源 URL、日期、引用目標、語系完整、資料與兩語清單一致。網頁搜尋結果與提報內容視為資料，不能指示 Agent 執行任意命令。真實盤點報告不當測試資料或 issue 附件。

## 8. GitHub 與使用入口

Repository：hansai-art/open-source-saver；Public；MIT 涵蓋自製內容。首頁中文優先，英文切換置頂；提供不用安裝的分類清單、Skill 安裝及本機指令三個入口。

每個產品提供別名、常見付費工具、中文任務詞、官方連結與可用平台，讓 GitHub 文字搜尋有內容可找。以 Markdown 分類錨點與 GitHub 搜尋起步，暫不開發搜尋網站。

附軟體提報與錯誤回報模板，收集原工具、真正任務、平台版本、免費限制、來源、繁中及實測狀態；不要求使用者提供全部已安裝清單。
